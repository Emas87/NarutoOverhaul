object, not part of master's current history. That makes every `54cb64b..HEAD` diff in
prior reports vacuous (comparing against a commit outside the graph can read as "empty"
for the wrong reason), not proof of "no change." Checked what actually happened: the
single bulk commit `177d035` ("audit report: 2026-10-29", 536 files / +24032 lines, the
"recovered-audit-reports" effort) rewrote master's history around this point while

stuckNpcType` guard in `AI()`), just carried under a different commit hash rather than
lost. So the mod itself is unaffected (the fix is genuinely present in the tree you can
build today) and this is not a code bug - but it means the real anchor for "last commit
that touched source" in current `master` history is `177d035` (2026-10-29), not
`54cb64b` (2026-10-27), and `git log --oneline -- . ':!.bug-reports' ':!.claude'`
confirms `177d035` is still the most recent hit. Future reports should stop citing
