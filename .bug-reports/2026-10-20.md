## Bugs

### Medium - OrochimaruBoss: a phase-transition substitution mid-Jump leaves `jumpLaunched` stuck true, so the *next* Jump attack skips its leap and fires the landing burst instantly
- Location: Content/NPCs/Bosses/OrochimaruBoss.cs:299-313 (`DoSubstitution`), 493-517 (`DoJump`)
- Description: `UpdatePhase()` runs unconditionally every tick, before the
  `switch (CurrentAttack)` in `AI()`. When life crosses the 66%/33%
  thresholds it calls `DoSubstitution`, which teleports the boss, sets
  `NPC.velocity = Vector2.Zero` (line 305), and forces
  `CurrentAttack = AttackState.Recover` (line 310) - but never touches the
  `jumpLaunched` field. If this fires while the boss is mid-leap
  (`CurrentAttack == AttackState.Jump`, `jumpLaunched == true`, boss still
  airborne), `jumpLaunched` is left `true` even though the state machine has
  moved on to `Recover`. `DoJump`'s own reset of `jumpLaunched = false` only
  happens inside its landing branch (line 516), which this path bypasses
  entirely. The stale `true` survives through `DoRecover` and into
  whichever attack is randomly picked next (`DoRecover`, line ~478); if that
  pick is `AttackState.Jump` again, `DoJump` enters with `jumpLaunched`
  already `true`, so it skips the telegraph/launch branch (`if
  (!jumpLaunched)`) completely and goes straight to the landing check
  `if (StateTimer > JumpTelegraphTicks && IsGrounded())` - which becomes
  true after ~22 ticks of the boss just standing on the ground (it never
  actually launched), firing `OnJumpLanding()` (impact VFX + player
  knockback within `JumpImpactRadius`) for a leap that never happened.
- Failure scenario: fight Orochimaru down past 66% or 33% HP while he
  happens to be in the middle of his Jump attack (a near-certainty over a
  full fight, since the player is normally actively damaging him and the
  Jump attack is one of three states picked every ~2-3 seconds). The very
  next time the RNG picks Jump again, he stands still for about a third of
  a second and then plays the landing flash/knockback without ever leaping
  - a visibly broken attack, reproducible in effectively every real
  playthrough.
- Suggested fix: in `DoSubstitution`, reset `jumpLaunched = false;` alongside
  the existing `CurrentAttack = AttackState.Recover;` - same shape as the
  fix just applied to `KakuzuBoss.UpdateElementPhase` for the identical
  mechanic (758b4fb). Guarding it with `if (CurrentAttack ==
  AttackState.Jump)` first (as Kakuzu's fix does) is the more defensive
  form, but since `jumpLaunched` is meaningless whenever `CurrentAttack !=
  Jump`, an unconditional reset in `DoSubstitution` is also correct and
  simpler.

### Medium - TailedBeastBoss: a phase-transition velocity zero mid-Jump fakes an immediate landing while still airborne
- Location: Content/NPCs/Bosses/TailedBeastBoss.cs:307-327 (`UpdatePhase`/`OnPhaseTransition`), 381-406 (`DoJump`)
- Description: Same `UpdatePhase()`-runs-before-the-switch ordering as
  `KakuzuBoss`/`OrochimaruBoss`. Here `OnPhaseTransition` (called from
  `UpdatePhase` at the 66%/33% HP thresholds) only does
  `NPC.velocity = Vector2.Zero;` - it does **not** change `CurrentAttack`.
  So if the boss is airborne mid-leap (`CurrentAttack == AttackState.Jump`,
  `jumpLaunched == true`, genuinely off the ground, `NPC.velocity.Y`
  nonzero) when a phase transition fires, `OnPhaseTransition` zeroes
  `velocity.Y` to 0 and then, in the very same `AI()` tick, the `switch`
  still dispatches to `DoJump()` (CurrentAttack was never changed) whose
  landing check is `if (jumpLaunched && StateTimer > JumpTelegraphTicks &&
  NPC.velocity.Y == 0f)` - now true purely because of the zeroing, not
  because the custom ground-scan in `ApplyGravityAndGroundCollision`
  (lines ~282-298, the function that normally produces a legitimate
  `velocity.Y == 0f`) ever ran. `OnJumpLanding()` fires at whatever height
  the boss happened to be at - mid-arc, possibly well above the ground -
  playing the landing VFX and pushing nearby players, then immediately
  drops into `Recover`.
- Failure scenario: fight Shukaku (TailedBeastBoss) down past the 66% or
  33% HP line while he is airborne during his Jump attack - again a
  near-certainty over a full fight. The landing burst and knockback trigger
  at that mid-air position instead of on actual ground contact, reading as
  a misplaced/early attack resolution and an unexplained shove while the
  boss is still rising or falling.
- Suggested fix: give `OnPhaseTransition` the same guard
  `UpdateElementPhase` got in `KakuzuBoss` (758b4fb): `if (CurrentAttack ==
  AttackState.Jump) { CurrentAttack = AttackState.Recover; StateTimer = 0f;
  jumpLaunched = false; }` before (or instead of relying on) the bare
  velocity zero, so the zeroed velocity can never reach `DoJump`'s grounded
  check in the same tick.
> Needs a decision: whether to fix each boss file's `OnPhaseTransition`/
> `DoSubstitution` individually (matches the existing per-boss duplication
> style, smallest diff) or pull the "end Jump safely" step into a shared
> helper first - see the duplication finding below, which this same bug
> class is evidence for.

## Improvements

### Duplication/robustness - extract the repeated "telegraph -> launch -> IsGrounded()-landing" Jump-attack shape shared by 3 bosses
- Location: Content/NPCs/Bosses/KakuzuBoss.cs:364-389 (`DoJump`/`jumpLaunched`), Content/NPCs/Bosses/OrochimaruBoss.cs:493-517, Content/NPCs/Bosses/TailedBeastBoss.cs:381-406
- Current: all three bosses independently define a `jumpLaunched` bool, a
  `JumpTelegraphTicks`/`JumpHorizontalSpeed`/`JumpVerticalImpulse` constant
  set, an `IsGrounded()` (or inline `NPC.velocity.Y == 0f`) check, and a
  `DoJump`/`OnJumpLanding` pair that is structurally identical apart from
  per-boss VFX/sound/damage numbers. The "a velocity-zeroing event elsewhere
  in the same tick can fake the grounded check" hazard this introduces was
  just independently discovered and fixed in one of the three copies
  (`KakuzuBoss`, 758b4fb) while the other two (today's bugs, above) still
  have it - direct evidence the copy-paste is already drifting out of sync
  under maintenance.
- Proposed: factor the shared shape (telegraph timer, launch impulse,
  `jumpLaunched` flag, the grounded-landing check, and a safe
  "AbortJump()"-style helper that resets `CurrentAttack`/`StateTimer`/
  `jumpLaunched` together) into a small shared base/helper that each boss's
  AI calls into with its own speed/impulse/VFX, so the next place this
  pattern is reused (or the next phase-transition/substitution/teleport
  added to any of these three) inherits the fix instead of needing it
  re-discovered per file.
- Risk: moderate - touches three live boss AI classes with their own
  per-boss quirks (Orochimaru's `IsGrounded()` is a named method,
  TailedBeast's is inlined and interacts with its own custom
  `noGravity`/`noTileCollide` ground-scan, Kakuzu's now has the extra
  element-phase-abort branch); a careless extraction could change jump feel
  (speeds/impulses are already per-boss constants, which is fine) or
  silently drop one boss's specific extra step (Kakuzu's
  `ChakraVFX.SpawnBurstEffect` tint switch, Orochimaru's sound choice).
  Best done as a mechanical, test-each-boss-individually refactor rather
  than a quick edit.
