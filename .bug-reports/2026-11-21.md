## Bugs
### Low - Shell sprite tools pass filenames to `convert`/`identify` without an `--` option/filename separator
- Location: `tools/convert_gemini_sprite.sh:55-56,61` (`identify -format "%w" "$input"` /
  `identify -format "%h" "$input"` / `convert "$input" -fuzz "$fuzz" -transparent
  "$bg_color" "$tmp1"`), `tools/prepare_sprite.sh:28` (`convert "$input" -fuzz "$fuzz"
  -transparent "$bg_color" -trim +repage "$tmp"`), and the caller
  `tools/land_icon.sh:24-26` (`latest=$(find ~/Downloads ... | sort -rn | head -1 | cut
  -d' ' -f2-)` fed straight into `convert_gemini_sprite.sh "$latest" ...` as `$1`).
- Description: `$input`/`$latest` are quoted (so whitespace in a filename is handled
  correctly), but nothing stops a filename that itself starts with `-` from being
  parsed by `identify`/`convert` as an option instead of a path - there is no leading
  `./` normalization and no `--` separator before the filename argument anywhere in
  these three scripts. `land_icon.sh` picks "most recently downloaded `.jpeg`/`.jpg`/
  `.png` file in `~/Downloads`" automatically, by mtime, with no name filtering, so
  whatever a browser saves a Gemini (or any other) download as becomes `$input`
  unexamined.
- Failure scenario: a file named e.g. `-depth 1.png` or `-write mpr:x.png` lands in
  `~/Downloads` (a crafted download filename, a browser "Save As" default that happens
  to start with `-`, or simply a manual `mv` while testing) and is the newest file
  there. `land_icon.sh` picks it up automatically and hands it to `identify`/`convert`
  as the first bare argument; ImageMagick's own CLI docs call this out by name as a
  footgun for exactly this reason (recommending `--` before filenames) - at minimum this
  silently breaks the pipeline with a confusing "unrecognized option" error instead of
  the expected image-conversion failure; at worst, a filename chosen to look like a
  recognized IM option/operator can alter what the `convert`/`identify` invocation
  actually does, rather than simply failing closed. `set -euo pipefail` does mean the
  script aborts rather than silently producing a corrupt icon either way, which bounds
  the real-world severity.
- Suggested fix: insert `--` before the filename argument in each `identify`/`convert`
  invocation (`identify -format "%w" -- "$input"`, `convert -- "$input" ...`), or
  normalize with a leading `./` (`convert "./${input#./}"`) before first use in
  `convert_gemini_sprite.sh` and `prepare_sprite.sh`.
> Needs a decision: this is a one-line defensive fix with no behavior change for every
> normal filename, so it's safe to apply without further discussion unless there's a
> reason these scripts intentionally stayed CLAUDE.md-simple.

## Improvements
### Missing defensive guard - `generate_armor_sheet.py build` silently drops a frame on a duplicate `--columns` index
- Location: `tools/generate_armor_sheet.py:230` (`frames_by_index = dict(zip(columns,
  frames))`, inside `build()`)
- Current: `columns` comes straight from `--columns` (comma-separated, user-typed) with
  no duplicate check. `slice_sheet` produces one frame per raw sheet column in order;
  `dict(zip(columns, frames))` then maps each frame to its target template index, and if
  two list entries repeat the same target index (a plausible typo, e.g. `--columns
  0,1,1,3` instead of `0,1,2,3`), the dict silently keeps only the later one - the
  frame meant for the skipped index is dropped with no warning, and the final sheet
  quietly reuses the wrong source frame for that slot. The sibling validation two lines
  above it (`len(frames) != len(columns)`) only catches a count mismatch, not a
  duplicate-target mismatch.
- Proposed: before building the dict, check `len(set(columns)) != len(columns)` and
  `sys.exit` with a message naming the repeated index(es), the same way the existing
  `--cols`/`--columns` length check and the `max_index` range check already fail loudly
  on a malformed invocation.
- Risk: trivial - a pure input-validation addition in a manually-invoked authoring
  script; no change to any already-working invocation.
