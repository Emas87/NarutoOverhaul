## Design decisions
### ShadowCloneProjectile - whether to cap concurrent Kage Bunshin clones per owner
- Report: .bug-reports/2026-09-23.md
- Location: Content/Minions/ShadowCloneProjectile.cs:77-101 (`FindTarget`); Content/Items/Weapons/Jutsu/ShadowCloneItem.cs:18 (`CloneCount`)
- The decision: whether to cap how many clones a single player can have alive at once - unlike
  the other minions, `ShadowCloneItem` has no cooldown beyond its Chakra cost and no check for
  existing clones before spawning more, so re-casting quickly can stack clones (and their per-tick
  target scans) without bound. The scan-throttling half of this run's finding (re-scan only every
  10 ticks, early-out once a target is "good enough") was applied and reviewed this run but
  discarded unverified (see above) - this decision is only about the separate clone-count-cap
  question.
- Options: A) No cap - leave clone count unbounded, accept the per-tick scan cost scales with
  concurrent clones (bounded some by the throttling fix once it lands). B) Cap concurrent clones
  per owner at a fixed number (e.g. 2-3) by tagging spawned clones with their owner and checking a
  running count in `UseItem` before spawning more. C) Add an explicit cooldown to
  `ShadowCloneItem.UseItem` beyond the Chakra cost, limiting re-cast frequency instead of a hard
  clone-count cap.
