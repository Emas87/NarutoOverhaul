## Design decisions
### `NarutoOverhaulConfig.EnableSoftBossScaling` is `ClientSide`-scoped but drives a server-authoritative effect
- Report: .bug-reports/2026-09-24.md
- Location: Common/Systems/NarutoOverhaulConfig.cs:9-17 (declared scope), read at
  Content/NPCs/Bosses/OrochimaruBoss.cs:199 and Content/NPCs/Bosses/KaguyaBoss.cs:187
- The decision: `OnSpawn` only runs on whichever machine calls `NPC.NewNPC` (the server in
  dedicated/host-and-play multiplayer), so the resulting boss stats are inherently one shared,
  session-wide decision - the opposite of what `ConfigScope.ClientSide` implies. A non-host
  player's own copy of this per-client toggle is never the one actually read.
- Options: A) Change `Mode` to `ConfigScope.ServerSide` (small, mechanical fix - matches what the
  code already does: one synced, authoritative value for the whole session) and correct the
  misleading doc comment. B) Redesign as genuine per-player difficulty scaling (bigger change -
  would need boss stats computed per-nearby-player rather than baked into one shared `NPC.lifeMax`
  at spawn, touching how stats are computed and synced).
