## Design decisions
### Shared "abort Jump safely" helper across 3 boss files
- Report: .bug-reports/2026-10-20.md
- Location: Content/NPCs/Bosses/KakuzuBoss.cs:364-389, Content/NPCs/Bosses/OrochimaruBoss.cs:493-517, Content/NPCs/Bosses/TailedBeastBoss.cs:381-406
- The decision: `KakuzuBoss`, `OrochimaruBoss` and `TailedBeastBoss` each
  independently duplicate the same "telegraph -> launch -> grounded-landing"
  Jump-attack shape (a `jumpLaunched` bool, telegraph/speed/impulse constants,
  a grounded check, a `DoJump`/`OnJumpLanding` pair). The identical "a
  velocity-zeroing event elsewhere in the same tick can fake the grounded
  check" bug has now been independently found and fixed three times (once per
  boss, the last two just this run) because there is no shared place to fix
  it once. Keep fixing each boss's handler individually (matches the existing
  per-boss duplication style, smallest diff, what was done this run) or
  extract a shared base/helper (telegraph timer, launch impulse,
  `jumpLaunched`, grounded-landing check, and a safe `AbortJump()` that resets
  `CurrentAttack`/`StateTimer`/`jumpLaunched` together) so the next
  phase-transition/substitution/teleport added to any of these three
  inherits the fix automatically.
- Options: A) keep duplicating the fix per boss as new copies of the bug turn
  up (lowest risk per change, but has already let the same bug ship three
  times) B) extract a shared helper/base now - touches three live boss AI
  classes with per-boss quirks (Orochimaru's `IsGrounded()` is a named
  method, TailedBeast's is inlined and interacts with its own
  `noGravity`/`noTileCollide` ground-scan, Kakuzu's has an extra
  element-phase-abort branch, plus per-boss VFX/sound differences), and there
  is no test runner here to verify a refactor across three bosses before it
  ships, so this would need to be verified by hand in-game, boss by boss,
  before merging C) leave as-is until the next instance of this pattern
  surfaces
