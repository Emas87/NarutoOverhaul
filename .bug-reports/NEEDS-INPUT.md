## Resolved this run (2026-09-17, verified via local `dotnet build` + real `.tmod` extraction)
- **The mod's 4 custom network packet handlers trusted a client-supplied player index instead of
  the real sender, letting any client forge another player's Chakra/Stamina/Transformation/
  MoonLordBlessing state** (high bug): `Common/Players/TransformationPlayer.cs`'s and
  `MoonLordBlessingPlayer.cs`'s `HandlePacket` now pick the write target as `Main.netMode ==
  NetmodeID.Server ? whoAmI : playerIndex` - trusting the tModLoader-supplied real sender when
  running as the server (where the payload's `playerIndex` byte is attacker-controlled), and only
  trusting the payload's index on the client (where it arrived via the server's own
  already-sanitized relay). The server also relays the *real* `targetIndex` downstream instead of
  echoing the attacker's claimed index. `ChakraPlayer.HandleCorrectionPacket` and
  `StaminaPlayer.HandleCorrectionPacket` now return early if `Main.netMode == NetmodeID.Server` -
  this packet type is only ever legitimately sent server -> client, so a copy arriving at the
  server means a client forged one, and it's dropped instead of overwriting authoritative state.
- **extract_tmod.py's rawimg decoder crashed with an unhelpful raw exception on a truncated or
  corrupt `.rawimg` entry** (medium bug): `rawimg_to_pil` now validates `width`/`height` are
  positive and that enough pixel-data bytes are actually present before slicing, raising a clear
  `ValueError` naming the shortfall instead of letting `Image.frombytes` fail with a generic
  traceback later.
- **extract_tmod.py's `extract` command raised a bare IndexError instead of the usage message when
  called with too few arguments** (improvement): added a `len(sys.argv) < 5` guard on the
  `extract` branch, mirroring the existing guard pattern used elsewhere in the file.

## Public API / format / contract changes
`ChakraVFX.SpawnBurstEffect<T>` changed from `private` to `public` (internal to this mod, not a
cross-mod API); the 15 removed wrapper methods were also internal-only. The packet-trust fix keeps
the wire format identical for all four handlers - only server-side trust logic changed (the server
now relays the real sender's index instead of whatever the sender claimed, which only matters if a
forged packet had been sent - a legitimate client's own index was always correct already). No
save/replay format touched.
