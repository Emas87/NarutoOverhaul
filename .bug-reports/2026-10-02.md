## Improvements

### Duplication - all 5 vanity village-headband items are byte-identical boilerplate
- Location: `Content/Items/Armor/LeafVillageHeadbandItem.cs:9-25`,
  `CloudVillageHeadbandItem.cs:9-25`, `MistVillageHeadbandItem.cs:9-25`,
  `SandVillageHeadbandItem.cs:9-25`, `StoneVillageHeadbandItem.cs:9-25`
- Current: `SetStaticDefaults` (`ArmorIDs.Head.Sets.DrawFullHair[Item.headSlot] = true;`) and
  `SetDefaults` (`width/height = 26`, `accessory = true`, `vanity = true`,
  `value = Item.sellPrice(silver: 5)`, `rare = ItemRarityID.Blue`) are copy-pasted verbatim across
  all 5 files, differing only in class name, namespace-comment, and (implicitly) the auto-resolved
  texture path. This is the same shape of duplication already flagged and accepted for fixing
  elsewhere in this codebase (`NumberedChakraScrollItem`, `BossBagItem`, `CombatStyleDamageClass`
  bases all exist specifically to eliminate this pattern) - these 5 items are the one remaining
  item family that still hasn't been collapsed.
- Proposed: Factor the shared body into a small `VillageHeadbandItem : ModItem` base (or an
  abstract class matching the `BossBagItem` idiom) that each of the 5 concrete classes reduces to
  just its `[AutoloadEquip(EquipType.Head)]` attribute and class declaration. Pure boilerplate
  reduction - no stat or balance change. A future tweak (e.g. adjusting vanity item value, or
  adding a 6th village) currently has to be copy-pasted into 5 files by hand instead of one.
- Risk: trivial - a straight refactor extraction with no behavior change; verifiable by diffing
  `SetDefaults()`/`SetStaticDefaults()` output before and after, or just a local build + visual
  check that all 5 headbands still show up correctly in the vendor shop.
