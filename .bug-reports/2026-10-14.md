## Improvements
### Duplication - The 6 animal-summon scroll items duplicate the same `SetDefaults`/`UseItem` shape, unlike every sibling numbered-item family in this codebase
- Location: `Content/Items/Weapons/BulldogHoundSummonScrollItem.cs`,
  `NinjaHoundSummonScrollItem.cs`, `ScoutHoundSummonScrollItem.cs`, `SlugSummonScrollItem.cs`,
  `ToadSummonScrollItem.cs`, `SnakeSummonScrollItem.cs` (44-48 lines each, 6 files)
- Current: Each file independently declares the same `SetDefaults` shape (`Item.width/height`,
  `useTime`/`useAnimation`, `useStyle = Swing`, `noMelee = true`, `UseSound`, `DamageType =
  DamageClass.Summon`, `buffType`, `shoot`, `shootSpeed = 1f`) and a byte-for-byte identical
  `UseItem` body (`player.AddBuff(Item.buffType, 2)` then, gated on
  `player.whoAmI == Main.myPlayer`, one `Projectile.NewProjectile(player.GetSource_ItemUse(...), ...)`
  call) - differing only in the numeric stats (`damage`/`mana`/`knockBack`/`value`/`rare`) and which
  buff/projectile type they reference. This is exactly the shape this codebase has already factored
  out three other times: `BossSummonItem` (base for the 7 story-boss summon items, extracted in
  `4acebf6` on 2026-10-08), `NumberedChakraScrollItem` (7 Chakra Scrolls), and `NumberedStaminaScrollItem`
  (7 Stamina Scrolls) - all abstract bases with a handful of `protected abstract` members and the
  shared logic written once. The animal-summon family was reviewed line-by-line on 2026-10-10 (per
  that report's own description) but only for correctness, not duplication, so this gap was never
  written down.
- Proposed: extract an `AnimalSummonScrollItemBase` (or similar) abstract `ModItem` with `protected
  abstract` `Damage`/`Mana`/`KnockBack`/`Value`/`Rare`/`BuffType`/`ProjectileType` members (or a
  constructor-style property group) holding the shared `SetDefaults`/`UseItem` body, the same
  mechanical shape as `BossSummonItem`. Cuts 6 files down to a handful of lines each with no
  behavior change.
- Risk: trivial - purely mechanical, the exact pattern already proven safe three times in this
  codebase.
