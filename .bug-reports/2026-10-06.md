## Bugs
### High - Fireball, Great Breakthrough, and Water Dragon projectiles never set `Projectile.DamageType`
- Location: `Content/Projectiles/FireballProjectile.cs:16-28`, `Content/Projectiles/GreatBreakthroughProjectile.cs:11-21`, `Content/Projectiles/WaterDragonProjectile.cs:24-35` (all in `SetDefaults`)
- Description: None of the three `SetDefaults()` bodies assign `Projectile.DamageType`, so each defaults to `DamageClass.Default` instead of `NinjutsuDamageClass`. First reported 2026-10-01, re-verified unchanged today (still no source commits since 2026-09-27).
- Failure scenario: a player stacking Ninjutsu damage/crit accessories, the Ninjutsu Mastery Scroll (+10% Ninjutsu damage), Ninjutsu armor set bonuses, or Sage Mode's generic boost gets none of the Ninjutsu-specific bonus on these three attacks, making them quietly underperform every other Ninjutsu jutsu (Rasengan, Chidori, etc., which do set it correctly) for a build that should favor them.
- Suggested fix: add `Projectile.DamageType = ModContent.GetInstance<NinjutsuDamageClass>();` inside each `SetDefaults()`, matching `RasenganProjectile.cs:50` and `ChidoriProjectile.cs:49`. Requires adding `using NarutoOverhaul.Common.Systems;` to all three files (not currently imported in any of them).
- Not fixed in-repo per this project's standing policy: fixes found by the automated routine are discarded unverified because this cloud environment has no tModLoader/dotnet build to confirm a change compiles (see `.bug-reports/NEEDS-INPUT.md`).
> Needs a decision: whether to add a headless build/compile check to this environment so routine-found fixes like this one-line addition can be verified and applied automatically, or keep manually applying fixes from the `NEEDS-INPUT.md` queue.
